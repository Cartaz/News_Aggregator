# Audit News Aggregator — 29 settembre 2026

## Oggetto e metodo

Audit del branch `main`, baseline `4b49250` (v1.1.0), rispetto al contratto Cartaz Desktop Application Standard — QML Compact. Sono stati letti i moduli di configurazione, core, adapter, shell/tray, QML, shader, installer e workflow CI, e verificati i test pertinenti. Non è stata effettuata una migrazione né riscritta l'architettura esistente.

La baseline superava 210 test con XDG temporanei. La prima esecuzione senza override ha rivelato che la fixture `tmp_paths` lasciava la cache favicon nella home reale; la fixture è stata corretta. Quattordici nuovi casi di regressione fallivano prima delle correzioni di configurazione, deserializzazione e feed vuoti.

## Problemi corretti

| Area | Problema osservato o identificato nel codice | Correzione e verifica |
|---|---|---|
| Impostazioni | Booleani testuali, dimensioni non intere/negative, limiti e intervalli non validi potevano diventare stato canonico; alcuni tipi causavano `TypeError` all'avvio. | Validazione di tutti i campi, valori numerici finiti, dimensioni entro 32.768 px e limite nativo del timer; test di rifiuto senza modifica dello stato. |
| UTF-8 | File settings/feed non UTF-8 interrompevano l'avvio. | Gestione esplicita di `UnicodeError`, con log e default/catalogo invariato. |
| Catalogo | URL non stringa potevano causare `AttributeError`; un solo articolo malformato poteva far scartare la sorgente valida. | Schema verificato, articoli invalidi isolati e segnalati, conservazione degli articoli validi e dello stato letto. |
| Date salvate | Date ISO senza timezone causavano confronti fra datetime naive e aware. | Migrazione in UTC alla deserializzazione; `source_id` degli articoli ricondotto alla sorgente proprietaria mantenendo ID e lettura. |
| Feed vuoti | RSS/Atom validi senza articoli venivano trattati come errori di parsing. | Successo con lista vuota per feed riconosciuti e non malformati; RSS e Atom verificati. |
| Limite articoli | `max_items_per_feed` veniva salvato ma ignorato; il parser si fermava comunque a 50 e il limite favoriva l'ordine del feed. | Controller e manager applicano il limite persistito; parser supporta fino a 500 articoli identificabili, manager conserva i più recenti. |
| Discovery | Un primo link RSS dichiarato ma non funzionante impediva di provare il secondo. | Tentativi ordinati sui link dichiarati, preservando cancellazione ed errori. Verificato con server HTTP locale reale. |
| Refresh | Un errore inatteso globale produceva `failed: 0`; timer cancellati potevano rischedularsi e il worker poteva essere osservato prima di partire. | Errore conteggiato, generazioni dei timer, registrazione/avvio del worker sotto lo stesso lock. Test di errore globale, timer obsoleti e lifecycle. |
| Conteggi | I badge delle singole sorgenti/categorie comprendevano articoli già esclusi dalla vista per età. | Conteggio dei non letti entro le stesse 48 ore del dominio. |
| Eventi UI | Rinomina, categoria, lettura o rimozione esterne lasciavano dettaglio/titolo/selezione obsoleti; cambi config non riallineavano il dettaglio filtrato. | Sincronizzazione tramite gli eventi canonici e risoluzione della selezione prima di costruire le righe. Test UI su stato e segnali. |
| Selezione QML | Reset del model e filtri potevano modificare l'indice come se l'utente avesse scelto un altro articolo. | Selezione operativa solo su click/tasti deliberati; indice `-1` riallineato. Verificato che filtrare non segni altri articoli come letti. |
| Focus | Il focus del dialogo andava al contenitore del campo, non al `TextInput`. | API di presentazione `focusInput()` e prova di digitazione reale nel dialogo. |
| Log | Lettura del file eseguita sul thread GUI; un risultato tardivo avrebbe potuto ripopolare un log chiuso. | Lettura tramite worker I/O posseduto dal controller, consegna Qt queued e invalidazione dei risultati dopo la chiusura. |
| Testo QML | `Text.AutoText` poteva interpretare markup residuo come testo ricco, anche con immagini remote. | `Text.PlainText`/`TextEdit.PlainText` espliciti; verifica sul testo articolo. |
| Tray | Nascondere la finestra senza un tray disponibile rendeva l'app irraggiungibile. | Nascondimento rifiutato con messaggio; la chiusura senza tray termina l'app. Il tray KDE reale non è disponibile nel display di test. |
| Shutdown QML | Lo smoke dell'installer emetteva molti `TypeError` quando gli adapter venivano distrutti prima delle binding QML. | Distruzione esplicita e idempotente di finestra/motore mentre gli adapter sono vivi; secondo installer e entry point senza questi errori. |
| Shader | La luce inset e l'accento non usavano l'alpha dei token, amplificando bordo e glow. | Composizione con alpha, token luce inset corretto e nuovo bake multi-backend; rendering OpenGL ispezionato. |
| Contratto visuale | Font canonico della versione esistente: Cantarell, mentre il contratto attuale richiede Noto Sans. | Noto Sans centralizzato in Theme, QApplication e installer; colori base/accento/testo preservati. |
| Installazione/CI | Possibile compilatore shader di sistema non abbinato; verifica limitata agli import Python. | Solo `pyside6-qsb` della `.venv`, controllo GLSL e caricamento reale di Main.qml con dati temporanei. Lint QML aggiunto alla CI. |

## Verifiche effettuate

Ambiente: Linux x86-64, Python 3.12.14, PySide6/Qt 6.11.2, Xvfb/X11 e OpenGL Mesa software. Sono state installate le librerie grafiche mancanti nell'ambiente di collaudo, incluso `libxcb-cursor0`.

- Suite completa: **241 test passati**, inclusi HTTP reale locale e interazioni Qt Quick.
- `compileall` su `main.py config core ui tests`; `bash -n install.sh`; `pip check`; `git diff --check`.
- `pyside6-qmllint --unqualified info -I ui/qml ui/qml/*.qml`: nessun warning/error nelle categorie mantenute vincolanti. Gli accessi alle context property e agli adapter `var` producono 227 diagnostiche informative: il lint non conosce i tipi forniti dinamicamente da Python. I percorsi sono verificati anche a runtime; questo non equivale alla verifica statica completa delle binding.
- QSB versione 9: SPIR-V 100, GLSL ES 100, GLSL 120/150, HLSL 50 e MSL 12. Variante GLSL verificata e shader usato nel rendering OpenGL.
- Installer eseguito due volte da `/tmp`, con `.venv` esistente: entrambi completati; il secondo smoke QML chiude senza `TypeError`.
- `main.py` eseguito con bootstrap dell'allocator e dati temporanei di collaudo: finestra 1280×800, selezione tramite mouse, dettaglio, preferenze, uscita tramite `Ctrl+Q`, codice 0 e nessun thread applicativo residuo. Il driver di collaudo avvia l'entry point e programma soltanto input, catture e un timeout di sicurezza che non è scattato.
- Catture della finestra e delle preferenze ispezionate visivamente; layout minimo 900×600 verificato dalla suite.
- Una lettura PSS durante l'avvio reale: **188.752 KiB (~184 MiB)**. È un singolo campione con rendering software, non un benchmark, un confronto A/B o una stima della RAM su CachyOS/RADV.

## Architettura e limiti del risultato

Python rimane proprietario di stato, persistenza, rete e concorrenza. QML usa modelli Qt per sorgenti e articoli; le liste sono virtualizzate e riutilizzano i delegate. I nuovi percorsi non aggiungono WebEngine, polling, processi esterni di produzione o un secondo proprietario delle impostazioni. Il log riutilizza il worker I/O esistente invece di creare un altro executor.

Non sono stati verificati direttamente il desktop CachyOS/KDE dell'utente, il driver GPU fisico, il tray/notifiche del suo desktop o l'apertura del suo browser. Le prove HTTP locali verificano il protocollo e la persistenza; non garantiscono che ogni sito remoto superi WAF, TLS o cambiamenti del proprio RSS. L'ispezione e i test non costituiscono una garanzia dell'assenza di ogni bug possibile.
